# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- A result named only in a kept part is no longer removed when that part was in the trash and is named again. A part whose entry is in the trash was not known for a part, so the clean-up that put it back did not count what it names, and removed it if the trash had held it over a week: the part then came back with tickets for results that were gone. That took a part going to the trash while still wanted, as when the disk its transcript is on is not mounted at a clean-up. What the transcripts name now goes back from the trash, with what the parts among it name, before the clean-up counts what is named; and a clean-up stops, moving nothing to the trash and removing nothing, where something named, by a transcript or by a part, is in the trash and not in its place.

### Added

- The benchmark tells a failure to fetch an answer from a failure after fetching it (#90). For each question whose answer no file holds any more, a unit of the plugin's arm that asks its questions one at a time records whether the answer still stood in the conversation, whether something moved out holds it, whether the agent called `recall` or `find`, whether it chose a piece that holds the answer, and whether what came back held it; `report` tables them. Measured with Sonnet 5.5 and no key for Jev (`bench/results/2026-10-05-fetched/`): 81 of 84 answers that had to be fetched were, where the oldest messages were cut once the results had left as where results alone left, and the three that were not are one question a run that another model answered after Sonnet 5.5 refused. `bench/main.ts find --variants default` measures `recall` alone without a key.
- `docs/invariants.md` says what "lossless" holds to, in eight promises, and what is not promised (#90): a ticket stands only for what was written, read back and found equal, a result, a long input, a long message and a run of folded calls alike; `recall` returns what was stored or nothing; what is stored is not written over; the clean-up removes nothing a conversation can still reach, and moves nothing when it cannot tell; what a cut takes out is kept first, and a summary does not run on a refused write; what went to the trash in use comes back; a conversation holding what a rebuilt message cannot carry is not rebuilt. Each promise names the tests that keep it, and `npm run mutate` breaks 31 lines of `src/` that the promises rest on, one at a time, and checks that the test named for each fails.
- The benchmark drives one session through several compactions under each of five settings: Claude Code's own compaction, the plugin with `targetPercent` at 40, 20 and 1, and the plugin moving results out before Claude Code summarizes what is left (#53, #90; `bench/main.ts session`, `bench/results/2026-10-05-session/`). With Sonnet 5.5 in a window of 200,000, two runs each: at 40 the session compacted five times and cost 5.02 and 5.13 USD, at 20 and at 1 four times (three in one run) for 4.03 to 4.23, the built-in three times for 3.85 and 4.03 with three of its five right answers read from Claude Code's own record of the session, and moving out before a summary left least in use and answered every question for 4.25 and 4.38. `docs/measurements.md` has the table: the compactions, what was in use before and after each, what the request after each read from the prompt cache and wrote to it, the cost at three points, the time and the answers.
- `PRIVACY.md` says what the plugin reads, keeps and where, sends and to whom, which programs it runs, how long it keeps what it kept and how to remove it (#89). The plugin itself sends nothing without a key for Jev, and nothing ever to the maintainer; with a key, `find` sends the provider what `docs/usage.md` lists. `test/privacy.test.ts` reads the code for the addresses, the programs and the places written in it, and fails when the page does not name one, or when the code sends another way than the one call `find` uses; it does not see one that the code puts together some other way. The README links to it.

- The middle of a long message leaves once results and long inputs are out (ADR 0024). A message of the person's or of Claude's of `minChars` characters or more, with three paragraphs or more, keeps its first and last paragraphs (500 characters of each at most, never cut inside a fenced block of code: where that would be the only cut, the message stays whole) and one line between them: `[moved out] the middle of this message; recall returns the whole message, 8622 bytes, head and tail included, with … id …`. The whole message is kept; the first message, the plugin's own lines, what Claude Code writes in the person's place (a notification, another session's message) and the newest such messages up to `keepTokens` of their own stay, but at a `/compact` typed without instructions, which reaches them up to the last thing the person said (ADR 0023). `find` sends Jev nothing of a middle that left: it looks through them here, in the conversation and in the kept parts it reads, for a quoted phrase or the values a question names, and names those that hold them beside its answer; a part kept before a summary is offered to Jev by its digest as before, and can hold what was said. A message the person sends again from a rewind, as its paragraphs and the line, goes in whole; a peer's message or a notification is not touched. A tool call of any tool but those known only to read, a tool of an MCP server and a subagent included, whose input holds a message's first and last paragraphs with the line dropped, is refused; where the two are under 40 characters together, only side by side. The line adds `, the middle of 1 long message`. In a real session (Claude Code 2.1.289, Sonnet 5.5, the default settings), a pasted document of 8,622 bytes and a `/compact` by hand: the conversation went from 8,786 to 483 characters and the next request from 7,376 to 5,083 tokens; asked with no tool, the agent said what it had been asked to do with the document and that its body was out of sight; asked for a value in the middle, it called `recall` and gave it; asked to save the document word for word, it called `recall` first and wrote the whole of it; sent again from a rewind, the message went in whole and the agent gave the value with no tool. Offline, the benchmark's `prose` and `full` conversations, mostly pasted text, came to 55 % and 52 % of their characters at a `/compact` by hand, where nothing could leave them before.
- A `/compact` typed without instructions reaches into the newest calls where moving out what is older is not enough (ADR 0023). Once every result, long input and old call older than the newest `keepTokens` is out, the same three are taken from the newer ones, up to the last thing the person said, not what Claude Code writes in their place (a turn stopped with Esc, a Stop hook's answer, a message another session sent, a command run with `!` and what it printed); the second round leaves that message and what came after it as they were, a call answered after it included. The line then says `; 4 of these from the newest turns`. In a real session (Claude Code 2.1.289, Sonnet 5.5, the default settings), a conversation of 10,908 characters that a `/compact` by hand left as it was before came to 2,617, the next request from 9,846 to 6,025 tokens; the person's last request and its answer stayed as they were, and asked for a value in a result that left, the agent called `recall` and gave it. Where a `/compact` is left undone, the line now says what takes the room, where the conversation was counted: what every request carries (the system prompt, tools, memory and the like), the first message, and the rest. A `/compact` by hand whose results or inputs could not be written is no longer left undone as if there were nothing to move out: the line says what was left in place and why, as it does at any compaction. A compaction Claude Code starts on its own, and a `/compact` with instructions, keep the newest `keepTokens` as before.
- Old small tool calls fold into a list once moving results and long inputs out is not enough (ADR 0022). A run of calls of `Bash`, `Read`, `Grep`, `Glob`, the tools that write, `WebFetch` and `WebSearch`, whose inputs and results are all short and hold no ticket, older than the newest `keepTokens`, leaves the conversation with its results, kept whole as a part; one message stands where it stood, naming each call and how many lines it returned, and the part's id.
